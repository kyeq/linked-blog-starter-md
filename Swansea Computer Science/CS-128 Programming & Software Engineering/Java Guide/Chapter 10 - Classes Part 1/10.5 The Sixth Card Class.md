# 10.5 The Sixth Card Class
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/10-dot-5-the-sixth-card-class)

This is all great – we now have methods that enforce some rules on the data held by our class, making it harder to end up with incorrect or inconsistent data. However, there’s a problem. Suppose we create a new class and call our methods like above:

```java
Card4 card = new Card4();
card.setNameValue("Ace");
card.setsuit("Spades");
```

**There’s nothing to stop us, after we’ve done this, from simply  *overwriting* the values we used (and checked with our methods) by  *directly* writing to the variables (or, remember,  *fields* ) in the class.**

```java
card.name = "Lemon";
card.value = 1066;
card.suit = "Lemon";
```

**This is like putting up a really secure front door but leaving all your windows open.**  To stop this happening, we need to  *restrict access* to the  *fields* name, value and suit. The way we do that is with the  **private**  keyword.

```java
public class Card5 {

     private String name;
     private int value;
     private String suit;

     public void setNameValue(String cardName){
          name = cardName; //sets the name
          switch(value) {
          case "Ace":    value = 1;
                     break;
          case "Two":    value = 2;
                     break;
          //others skipped to make it shorter
          case "King":   value = 10;
                     break;
          default:  value = -1; //An error value
                     name = "error";
                     break;
          }
     }

     public void setsuit(String suit){
          if(suit.equalsIgnoreCase("Hearts") ||suit.equalsIgnoreCase("Diamonds") ||
               suit.equalsIgnoreCase("Clubs") ||    suit.equalsIgnoreCase("Spades")) {
               this.suit = suit;
          } else {
               this.suit = "error";
          }
     }

     public String toString(){
          return (name + " of " + suit);
     }
}
```

Notice we’ve put the keyword private (in italic and bold, just to make it stand out a bit more), in front of the declarations of the variables we are using.

### KEY POINT: Public, Private Etc.

By now the point of the keyword public should also be clearer:

- Anything preceded by public is visible outside whatever it’s in - in our case,  *outside*  the class Card6.
- Anything preceded by private is not visible outside the (in this case) class –  *only inside.*

There are actually four possible options we can have in Java

| **Option** | **Meaning** | **Comment** |
| --- | --- | --- |
| public | Visible outside the class of the item it is attached to – in our case, field or method | Use this whenever you want something to be accessed from outside a class |
| private | Not visible outside the class of the item it is attached to | Use this whenever you don’t want something to accessed from outside a class |
| protected | Visible outside the class but only to other things in the package or to subclasses | *Best not to use this since we haven’t done subclasses and packages* |
| nothing | Visible outside the class but only to other things in the package | *See above* |

In practice, for this module, we should stick to public and private – they have meanings that make sense in terms of what we’ve done. Using protected (which basically means “a bit less public than public”) or nothing at all (“ bit less public than protected”) doesn’t really help us in this module.

Here’s an example of using Card6:

```java
public static void main(String[] args){
	  Card6 card = new Card5();

	  //Now we set name and value
	  card.setNameValue("Ace");
	  card.setsuit("Spades");

	  System.out.println(card.toString());

	  System.out.println(card.value);
	  System.out.println(card.name);
	  System.out.println(card.suit);
}
```

This seems straightforward enough – we have created our Card6 class, initialized a card to be the Ace of Spades, and then printed it out using both toString() and by printing the value, name and suit directly

**The trouble is it does not compile!**

You get an error message something like this (exact text will depend on the name of the file you use to test your card class).

**TestCard5.java:16: error: value has private access in Card6**

**System.out.println(card.value);**

**^**

**TestCard5.java:17: error: name has private access in Card6**

**System.out.println(card.name);**

**^**

**TestCard5.java:18: error: suit has private access in Card6**

**System.out.println(card.suit);**

**^**

**3 errors**

This is because, of course, we made value, name and suit private!  **We can no longer (directly) access them**  – and that means that not only can we not  *change*  them, we also cannot  *read*  them. We  *can*  set them because setsuit() and setNameValue() are public; we can also print them as a string because toString() is also public. The public methods are visible from outside the class and they can access the private variables because they are all (methods and variables) in the same class. But the variables themselves are private and so we can’t directly read them – the way to fix this is to add  *accessor* , or  *getter* , methods. These are just methods to access the values stored in private fields. In the case of Card6 we just need to add these three:

```java
public String getName() {
	  return name;
 }

 public int getValue() {
	  return value;
 }

 public String getsuit() {
	  return suit;
 }
```

These three methods are public so  *can*  be called from outside the class – so we can update the code that did not compile:

```java
public static void main(String[] args){
	  Card6 card = new Card6();

	  //Now we set name and value
	  card.setNameValue("Ace");
	  card.setsuit("Spades");

	  System.out.println(card.toString());

	  System.out.println(card.getValue());
	  System.out.println(card.getName());
	  System.out.println(card.getsuit());
}
```

Now we are calling our public getter methods we can access the values in the fields – because the methods return those values.

### KEY POINT: Get/Set, Accessor/Mutator, Getter/Setter Methods

As stated above methods that return values from a class are called one of  *get methods, accessor methods* , or  *getter methods*  – they have names that start with  *get* . There is nothing special about them – they are just methods – or of using names starting with  *get*  – it just indicates to the reader what they do. It is good practice so stick to it.

Similarly, methods that set the value of things are called (one of )  *set methods, mutator methods,*  or  *setter methods*  – they have names starting with  *set* . Again, this is not special – it’s just a standard convention to make reading programs easier. So, again, stick to it.

A special variation on using  *get*  with getter methods is when the value being returned is a boolean. Then the name usually starts with  *is* . For example, the ArrayList method isEmpty() which returns true when an ArrayList is empty.
