# 10.2 Applying Object Oriented Ideas in Practice
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/10-dot-2-applying-object-oriented-ideas-in-practice)

Over the rest of this chapter (and the next) we’re going to show how to apply these object oriented ideas in practice to code. We are going to do this in stages.

- We will start with showing how to group data together.
- How to write methods that interact with our data.
- How to prevent anyone directly accessing our data.
- How to customize how our objects, and data, are created in the first place.

We'll do this by building an example in stages - adding on more things to solve problems and make it better.  *You can find all the card example programs at the end of [this chapter](https://canvas.swansea.ac.uk/courses/68227/pages/card-classes-1-6) and the [next one](https://canvas.swansea.ac.uk/courses/68227/pages/card-classes-7-10).*

### Word of Warning

Because we are building in stages the first examples you will see are not good practice -  **you really need to read ALL this chapter AND the next to know exactly how you should use classes and objects.**

### Another Word of Warning for Those with Previous Experience

It is easy to get carried away and do all sorts of "advanced" OO things for coursework 2 - which generally means  *inheritance.* But (a) that's not in the course content for this module anyway; and (b) after initially (at the start of the OO programming 'boom') thinking inheritance was great for everything, we now know it has some significant drawbacks: it is still very important, but in more controlled circumstances. So don't do it.

### The First Card Class

We’re going to build a *playing card*  class that includes a  *value* , a  *name*  and a  *suit (* for those of you unfamiliar with playing cards, [this](https://en.wikipedia.org/wiki/French-suitd_playing_cards) might be helpful but it's not hugely important). Values will range from 1 to 10; names will be the traditional names of playing cards; and suits will be one of ‘spades’, ‘clubs’, ‘hearts’, ‘diamonds’. Here’s the code of the first version.

```java
 public class Card1 {
     String name;
     String suit;
     int value;
}
```

All we have done is create a class but instead of putting  *code*  into it we’ve just put  *variables* . Each variable - technically now called a  *field*  because it isn't inside a method - represents one piece of the data associated with a playing card. So the Card1  *class*  is the ‘template’ for a playing card, and we need to create card  *objects*  of this class, then put in actual data. How do we do this? Here’s a main method:

```java
public static void main(String[] args){

          Card1 card = new Card1();

          card.name = "Ace";
          card.value = 1;
          card.suit = "Spades";

          System.out.println("Card: " + card.name + " of " + card.suit);
          System.out.println("Value: " + card.value);

          //Now make another one
          Card1 anotherCard = new Card1();
          anotherCard.name = "King";
          anotherCard.value = 10;
          anotherCard.suit = "Hearts";
          System.out.println("Another Card: " +
               anotherCard.name + " of " +
               anotherCard.suit);
     }
}
```

The first line:

```java
Card1 card = new Card1();
```

*creates*  a new Card1  *object* .

### KEY POINT: Creating Objects from Classes

In general, when we create a class we write something like this:

```java
ClassName objectName = new ClassName(...);
```

where we may pass in some parameters (in place of the …) between the brackets after ClassName. When we do this we are calling a piece of code called a  *constructor*  – more about these later: for now, the Card1 constructor doesn’t have any parameters.

There are other ways of creating objects but this is the most common and basic.  *It should be clear that we’ve seen this many times already.*  For example:

```java
Scanner in = new Scanner(System.in);

Random rnd = new Random();

ArrayList<String> list = new ArrayList<>();
```

creates new  *objects*  of the Scanner, Random and ArrayList  *classes* . (If you’re wondering about how <String> fits in, you can write your own classes that do things like that, but we won’t in this module – things in <..> are called  *generics* and are a bit more advanced.)

### Accessing Elements of a Class

If you look at the main method above you will see the lines:

```java
card.name = "Ace";
card.value = 1;
card.suit = "Spades";
```

This is the way we access elements – or  *members*  – of a class. The name of the  *object*  (card in this case) goes before the ‘.’ and the name of the  *member*  (name, value, suit) go after it. We can both assign to members:

```java
card.suit = "Spades";
```

and read their values:

```java
System.out.println("Card: " + card.name + " of " + card.suit);
```

which in this case prints out ‘Ace of Spades’.

#### Word of Warning

In real object-oriented programming we NEVER directly access the variables (fields) like this and ALWAYS use methods (more on this later).  **We are only doing it here to show how we 'build' the concepts of classes and objects from the basic idea.**

### KEY POINT: Fields

In this case, our class only contains  *variables* (we’ll put other things in later). Commonly, people just use the term  *variables* for these but strictly speaking in object oriented programming variables in a class like this are called  *fields.*

You can of course create as many objects of a class as you want – just as you can make as many models of a car as you want; or open as many branches of Lidl as the owners want. In the example above

```java
Card1 anotherCard = new Card1();
```

creates a second card object. This second card will contain  *separate* copies of the fields (variables) in the Card1 class.

### Printing out an Object

In the example above, the line:

```java
System.out.println("Card: " + card.name + " of " + card.suit);
```

prints out ‘Ace of Spades’. But this seems a bit clumsy. What happens if we just do:

```java
System.out.println(card);
```

If you try this, you get something like:

**Card2@eb42cbf**

which seems like gibberish. Actually, it’s the name of the class (Card), followed by ‘@’ and then a  *hashcode* computed from the data stored in a particular object in  *hexadecimal* . This isn’t very helpful, so we need to change it (and will in a bit).

### The Second Card Class and Multiple Files

If you look at the example programs, you'll see that there is a Card2 class which has a separate related file called TestCard2. ### Classes and Methods

As well as variables, classes can contain  *methods*  – and they actually come with some ‘for free’ that we don’t have to write. One of these is called toString() which is called whenever you do something with a class that ‘expects’ a value that’s a string (like printing it). You can also call this method explicitly if you want – this:

```java
System.out.println(card);
```

is the same as this:

```java
System.out.println(card.toString());
```

This is the one that prints the Card@ gibberish we saw above - we'll fix that soon.

### KEY POINT: Calling Methods in Objects

By now, the notation ‘objectName.method(…)’ should be obvious to you – it’s  *exactly*  what we’ve been doing when we write things like:

```java
in.nextLine();
```

We are calling a  *method*  called nextLine() belonging to an  *object*  in (which is an  *instance*  of the Scanner class, in this called  *in* ).
