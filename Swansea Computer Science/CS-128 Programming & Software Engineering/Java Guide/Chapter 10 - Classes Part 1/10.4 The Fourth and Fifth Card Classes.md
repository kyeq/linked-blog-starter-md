# 10.4 The Fourth and Fifth Card Classes
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/10-dot-4-the-fourth-and-fifth-card-classes)

One obvious point about cards is that they don't allow just any value for, say, the suit - it has to be one of 'Hearts', 'Diamonds', 'Clubs' or 'Spades'. Similarly, the value of the card and its name are not independent: if we set the name to "Two" the value should not be 5. Can we do something to enforce that? Yes - we can write methods to set the the data so only correct values are allowed.

### Advanced Aside

There are actually 'nicer' ways of doing some of this - but that's for a later module.

### The Fourth Card Class

We'll start off by writing a method to set the value and name.

```java
public class Card3 {

	String name;

	int value;

	String suit;

	// Here's our method
	public void setNameValue(String cardName){

		//We could use a switch statement here
		if (cardName.equalsIgnoreCase("Ace")) {
			value = 1;
			name = cardName;
		} else if (cardName.equalsIgnoreCase("Two")) {
			value = 2;
			name = cardName;
		} else { // You get the idea - I'm bored now and I'll skip the rest except...
			value = -1; // to indicate an error - which raises questions...
			name = "error";
		}
	}

	// We'll leave in toString()
	public String toString(){
		return (name + " of " + suit);
	}
}
```

Now we don't directly set the name and the value - we call the method setNameValue using just the name, and our code  *works out*  the value (meaning they cannot be inconsistent). For example, if we said card.setNameValue("Ace") value would automatically get set to 1.

### The Firth Card Class

Now we'll extend our class to include a method that also sets the suit and only allows correct values.

Instead of repeating the whole class, we’ll just write the extra method we need.

```java
 public void setsuit(String suit){
	  if(suit.equalsIgnoreCase("Hearts") ||suit.equalsIgnoreCase("Diamonds") ||
		  suit.equalsIgnoreCase("Clubs") ||    suit.equalsIgnoreCase("Spades")) {
	      this.suit = suit;
	  } else {
	      this.suit = "error";
	  }
 }
```

This sets the value of the suit to “error” if we try to call a suit anything other than Spades, Clubs, Diamonds or Hearts (this is a bit basic as error handling goes but it will do for this module: later you will see better ways to do this).

**Notice I have introduced a new keyword**  - this -  **in the code above.**  The keyword this just means 'the current object' and I will explain it below. I'm only using it here because I am using the same name for the argument of the method and for the field in the object: they are both called suit. If you don't want to get into what this means, you can just change the name of the argument to something else - e.g. suitArg in the example below:

```java
 public void setsuit(String suitArg){
	  if(suitArg.equalsIgnoreCase("Hearts") ||suitArg.equalsIgnoreCase("Diamonds") ||
		  suitArg.equalsIgnoreCase("Clubs") ||    suitArg.equalsIgnoreCase("Spades")) {
	      suit = suitArg;
	  } else {
	      suit = "error";
	  }
 }
```

Here’s how we would call setsuit:

```java
 public static void main(String[] args){

	  //As before...
	  Card4 card = new Card4();

	  //Now we set name and value
	  card.setNameValue("Ace");
	  card.setsuit("Spades");

	  System.out.println(card);

	  // Lets test the 'error handling'
	  Card5 wrongCard = new Card5();

	  wrongCard.setNameValue("Lemon");
	  wrongCard.setsuit("Grapes");

	  System.out.println(wrongCard.toString());
 }

```

The output of this will be – for the first card:

**Ace of Spades**

and the value would have automatically been set to 1. For the second – wrong – one:

**error of error**

As we said, this isn’t  *great*  error handling – but it’s better than nothing and you'll see better ways in CS-115.

### The Keyword This

We introduced a new keyword called this in the code above. The keyword this just means 'the current object' (i.e. 'this object'). We use it when we want to refer to something linked to the current object. In the example above (setsuit) we just wanted a way to tell two things apart: the field representing the suit in the class and the argument to a method. We wanted to use the same (obvious) name but because they are the same, this would be a problem. Here's a cut-down version of the code with the key points labelled:

```java
public class Card5 {

	...
	String suit; //<- this has the same name as...

	public void setsuit(String suit) { //<- .. this

		if (...) {
			this.suit = suit;
		} else {
			this.suit = "error";
		}
	}
}
```

If we didn't do something about it, and just wrote suit = suit; then Java would just set the value of the  *parameter* to the value of the  *parameter* (i.e. do nothing). The value of the field would not change at all. By writing this.suit we fix this. The keyword this means the current object, so this.suit means 'the identifier suit belonging to the current object' - i.e. the one near the top.

I **f you don't want to get into this right now, or are finding it unclear then just make sure you use different names**  - just changing the name of the parameter means we do not have to use this in the example above.

### Advanced Aside: Other Uses for This?

You can use the keyword this in other contexts - one use is when you are using  *inheritance* which we are not going to go into here. But here's another example: suppose you want to write a class that, when an object is created it adds  *itself* to some ArrayList?

```java
public class MySelfAddingClass {

	private ArrayList<MySelfAddingClass> list = new ArrayList<>();

	public void MySelfAddingClass() {

		list.add(this);
	}

	//More code here
}
```

This class contains a list of objects of its own class - the constructor uses the keyword this to add the object that is being created to that list. (You should know this can be risky in  *multithreaded*  code, but that's for another year).
