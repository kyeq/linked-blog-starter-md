# 8.8 The For-Each Loop and Abstraction
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/8-dot-8-the-for-each-loop-and-abstraction)

Arrays and ArrayLists let us make sense of a ‘new’ kind of loop – which we saw briefly in the last video in the last section - called the  *for-each*  loop. It’s really a variation on a for loop but it’s more  *abstract*  (which is a good thing as we’ll explain). Here's an explanatory video:

> [!note] There is a video for this on the Canvas page.

One thing you quickly discover in programming is that you often have to go through structured data (like an array or ArrayList; or one of the others like those listed at the start of [section 8.6](https://canvas.swansea.ac.uk/courses/68227/pages/8-dot-6-arraylists-an-alternative-to-arrays)) and do something to each element. Suppose for example you just want to do something simple - print out each element in an array of integers called data. The ‘traditional’ code for an array (assuming it’s full and we can use data.length) looks like this:

```java
for (int i = 0; i < data.length; i++) {
     System.out.println(data[i]);
}
```

and for an ArrayList it looks something like this:

```java
for (int i =0; i < data.size(); i++) {
     System.out.println(data.get(i));
}
```

These are clearly different. Suppose we’d started off using arrays and then changed to an ArrayList – we would have to go through the code and rewrite it. If there were lots of places in our code where we were looping through an array (which is actually very common), this is a lot of work. But  *conceptually*  we are doing the same thing in each case and the only reason the code is different is the details of the way we are storing the data. If we could ‘step back’ from the detail and just tell Java – ‘print out every element in my structured data’ then maybe we could eliminate the differences. We can using a  *for-each loop* :

```java
for(int item : data) {
     System.out.println(item);
}
```

In this loop, the value of the variable item is  *successively*  set to the elements of the array in turn.

So, what if data is an ArrayList instead? The code looks like this:

```java
for(int item : data) {     System.out.println(item);
}
```

*So it does not matter if data is an array or* ArrayList *- the code is the  **exactly**  the same.*

The format of a for-each loop is:

```java
for (type name : list)
```

where:

- type is the data type of the items in the array/ArrayList (e.g. int, String)
- name is an identifier  *you choose*  to represent each data item in your list – you use this name to represent each item in your array/ArrayList in the body of your for-each loop. Just pick a sensible name like you would with any other variable.
- list is the name of the list of data (array/ArrayList) you are processing.

The for-each loop is a more  *abstract* way of representing the same loop –  **and it’s exactly the same for arrays and**  **ArrayLists.**  In fact *, it’s the same for all the ways of representing structured data in Java*  (and there are many more ways of doing it than we have seen).

### Key Point: Use For-Each Loops When Processing Arrays or ArrayLists

If you’re systematically processing an array or ArrayList you should us a for-each loop instead of a ‘normal’ for loop.

### Key Point: Abstraction

For-each loops are good because:

- **They are simpler**  – there are less things you can do wrong.
- **They are more abstract**  – they say  *what*  you want to do not  *how*  it’s done.

Abstraction is what makes it possible for them to be the same for both arrays and ArrayLists.  *Abstraction*  is a key concept in Computer Science – we try to develop abstract solutions because they are easier to understand and apply to a wider range of problems without change.

### Key Point: Imperative vs Declarative

The 'old' style loop is  *imperative -* meaning we are saying  *how* we want the computation to happen:

"create a variable, set it to zero. Then as long is it's not got to the end of the array (or arraylist) go and do something to the array (or arraylist) element referred to by the current value of that variable. Then add one to the variable".

You can see it's a list of 'how-to-do-it' steps.

The 'new' style is  *declarative -* meaning we are just saying  *what* we want to happen, not how:

"do something to each element of the array (or arraylist) - you sort out the details, I'm not interested."

### Foreach Loop Example

We’re going to look at a few examples of programs that use for loops and foreach loops, and the differences between them using arrays and ArrayLists. The first program just prints out a list of shapes from an array (leaving out the import statements):

```java
public class ShapeList {
     public static void main(String[] args) {

          final String[] SHAPE_NAMES = {"Triangle",
               "Square","Pentagon", "Hexagon",
               "Heptagon", "Octogon",
                "Nonagon", "Decagon"};

          for(int i = 0; i < SHAPE_NAMES.length; i++) {
               System.out.println(SHAPE_NAMES[i]);
          }
     }
}
```

Now suppose we change this so it uses an ArrayList:

```java
public class ShapeList {
     public static void main(String[] args) {

          Random rnd = new Random();

          final String[] DATA = {"Triangle",
                 "Square","Pentagon", "Hexagon",
                  "Heptagon", "Octogon",
                 "Nonagon", "Decagon"};
          //This line just turns an array into an ArrayList - it's the easiest way to make one quickly
          final ArrayList<String> SHAPE_NAMES =
                        new ArrayList<>(Arrays.asList(DATA));

          for(int i = 0; i < SHAPE_NAMES.size(); i++) {
               System.out.println(SHAPE_NAMES.get(i));
          }
     }
}
```

The parts of the  *loop only* that need to be changed are in  **bold**. Now here’s the first example with a foreach loop:

```java
public class ShapeList {
     public static void main(String[] args) {

          Random rnd = new Random();
          final String[] SHAPE_NAMES = {"Triangle",
               "Square","Pentagon", "Hexagon",
                "Heptagon", "Octogon",
                "Nonagon", "Decagon"};

          for(String shape : SHAPE_NAMES) {
               System.out.println(shape);
          }
     }
}
```

If we change this one to use an ArrayList:

```java
public class ShapeList3 {
     public static void main(String[] args) {

          Random rnd = new Random();

          final int MAXSHAPES = 8;
          final String[] DATA = {"Triangle",
                  "Square","Pentagon", "Hexagon",
                   "Heptagon", "Octogon",
                 "Nonagon", "Decagon"};
          final ArrayList<String> SHAPE_NAMES =
                       new ArrayList<>(Arrays.asList(DATA));
          //The loop we need is IDENTICAL
          for(String shape : SHAPE_NAMES) {
               System.out.println(shape);
          }
     }
}
```

**Notice the loop is exactly the same**  –  *we can change how we store the shape data and we do not have to change any of the rest of the code.*

### Very Advanced Aside: Lambda Expression

Version 8 of Java introduced a new concept called  *Lambda Expressions*  (named after the λ calculus – a key concept in  *functional programming* ). Lambda expressions allow a wider range of options for various things in Java, including for-each loops. For example, we can re-write the loop that adds one to elements of an array or ArrayList above like this:

```java
items.forEach(item -> System.out.println(item));
```

or even like this:

```java
items.forEach(System.out::println);
```

They are handy, especially for  *parallel programming* – but conceptually quite complex. If you have a fair amount of programming experience already and want to research (and use) them, that’s fine (and they are now very widely used especially by 'top' employers). There’s no need to at this stage - but there is material (optional) on this is [section 8.10](https://canvas.swansea.ac.uk/courses/68227/pages/8-dot-10-advanced-optional-extra-lambdas-and-streaming).

### Advanced Aside: Why are they called 'for each' loops?

You may have noticed that except in the Lambda Expression version for-each loops actually just use the word ‘for’ and not ‘for-each’ (or ‘foreach’). The reason they are called for-each loops is that the concept as it’s used in Java originated in another language called C#, which does use the word ‘foreach’.
