# 1.6 A Program With Input
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/1-dot-6-a-program-with-input)

Obviously “Hello World!” is ridiculously basic – for one thing, it  *always*  does the same (not very interesting) thing. How about a program that accepts some input and does something with it?

For example, here’s a simple dialogue with a program that asks you your

name and then says hello:

**>What is your name?**

*Neal*

**>Hello Neal!**

Let’s think about the  *sequence*  of events going on here – the  *Algorithm*  that the program must  *implement.*

1. Step 1 – Print out message “What is your name?”
2. Step 2 – Read in input from user  *and store it*
3. Step 3 ­– Join user input with “Hello “ and “!” and output result.

The KEY POINT for us here is  *storing*  data – because we need to do that in this program: we need to remember whatever the user typed in so we can output it later.

Before we get on to actually writing a program that deals with input, we need to work out how to  *store*  input, which means learning about  *variables.*

### KEY POINT: Variables

Computers store  *data*  in  *memory* , and computer memory is just a very long list of numbered ‘boxes’ in which you can put that data. But it’s very difficult to deal with memory directly. There are usually  *billions*  of these numbered boxes (so dealing with the numbers – or  *memory addresses –*  is difficult for humans); each 'box' can only hold a small piece of data; and also your program might not end up in the same bit of memory every time it runs (so the numbers can change). We fix this by using  *names*  for the data we store, and letting the computer work out which memory ‘boxes’ to put it in, how many 'boxes' to use, and what the data in the 'boxes' actually represents. We just worry about the names.

The names we use are another example of  *identifiers* . But this time instead of identifiers that name programs we are talking about identifiers that name  *stored data*  – we usually call these identifiers  *variables*  .

### The Code: What does this look like in Java?

Before we get into the details about variables here's a basic program to deal with input - ask your name, and say hello. We're going to use this to illustrate and motivate what variables are and why we need them.

```java
import java.util.Scanner;

public class HelloYou {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.println("What is your name?");
        String name = in.nextLine();
        System.out.println("Hello " + name + "!");
    }
}
```

Some of the lines in this new program are the same or very similar to our last one. But some are clearly different. We’ll look at the key lines below. But the three lines:

```java
System.out.println("What is your name?");
String name = in.nextLine();
System.out.println("Hello " + name + "!");
```

are the ones that correspond with our algorithm above. The first one just prints out “What is your name? “ and is very similar to the “Hello World!” example – but the others are slightly more complex.

### Creating, or  *Declaring* , Variables

String name = in.nextLine(); - this line is the one that creates a new variable called name. That is, name is an identifier that in this case represents some stored data. The  *type*  of the stored data is  String.  *Types* in programming languages refer to the kind of a piece of data (or the variable you put it in). There are many types in Java - as well as  *Strings*  there are numbers (different kinds) and others, simple and complex (and you can create your own too). A  *String*  is a sequence of characters (i.e. a ‘string’ of characters joined together).  String  is a very commonly used  *type*  in Java (and most other languages). A single word (e.g. “Java”) is a string; a sentence is a string (“Java is the language we use in this module”); even this whole chapter is a string – a string is  *any*  sequence of characters (and the characters do not have to be from the Latin alphabet – so "Hello" is a string, and so is “Γειά σας!”; and "مرحبا"; and "你好" - any sequence of symbols is a string). You may have noticed that you had to type String  when you entered the line:

```java
public static void main(String[] args) {
```

and you might think that args is some kind of String variable (you would be right); but that the ‘[]’ does something ‘funny’ to it (you’d be right about that too).

How do we know to call the variable we are using name?  *We don’t*  – just like the program name,  *we can choose what we call variables.*  But it makes sense to  *pick names that help you understand what data you are storing in them* . Because in this case the variable is supposed to represent data corresponding to somebody’s name, it makes sense to call it name. REMEMBER - HUMANS READ PROGRAMS and need to understand them;  *the computer does not care but you do.*

To create, or  *declare*  , a variable in Java we need to state both the  *type*  and the what we want to call it. So this is a perfectly good declaration:

```java
String name;
```

Notice that this is a simple statement, like those described above, and it ends with a “;”.

The ‘problem’ with this is that we have not told Java  *what*  data is stored in name – just that it’s a string of characters, and it’s called name. Sometimes that’s what we want to do – for example, we might not  *know*  when we create a variable what data we will be putting in it. However, very often we do and so we can  *initialize*  a variable at the same time we  *declare*  it:

```java
String name = "Neal";
```

This sets the initial value of the variable name to the  *String literal*  “Neal”.

### Simple Assignments

Another way of doing this is in two steps

```java
String name;name = "Neal";
```

That is, we first declare the variable, and then separately set it to the value we want – this is equivalent to the single statement that does both. Statements of the kind

```java
variable = value;
```

in Java are called  *assignments,*  or  *assignment statements.*  There is no reason why we can’t then  *change*  the value of a variable with  *another*  assignment. For example:

```java
String name;name = "Neil"; name = "Neal";
```

The value stored in name changes as the program runs, as you can see in this table:

| **Line** | **Value stored in name** |
| --- | --- |
| String name; | - |
| name = “Neil”; | Neil |
| name = “Neal”; | Neal |

It’s a bit boring if we are only able to set variables to fixed  *literal*  values. We can do much more than this of course – more later. But for now, one thing we can also do is set one variable equal to another.

```java
String fruit;String citrus = "Lemon";fruit = citrus;
```

First we create a variable called fruit with no value; then we create a variable called citrus with value “Lemon”, then we assign the value stored in citrus to the variable fruit. At the end of this, the variable fruit has the value “Lemon” – and so does citrus because assignments copy data; so setting fruit to the value of citrus does not change citrus. The table below shows the steps.

| **Line of Code** | **Value of fruit** | **Value of citrus** |
| --- | --- | --- |
| String fruit; | - | Does not exist yet |
| String citrus = “Lemon”; | - | Lemon |
| fruit = citrus; | Lemon | Lemon |

### Key Point: Variables Contain One Thing at a Time

You can change the value stored in a variable – we did that with the one called name that first held ‘Neil’ and then ‘Neal’. The way you change the contents is by an assignment. But:

- Variables can only contain one piece of data at a time.
- Once you assign a new value to a variable, the old value is lost.

### Aside: Blank Lines

Notice we’ve put a blank line in our program above – you never need to do this, but it can be handy to break your program into “logical blocks” and make it easier to read. But don't just put them in randomly - use them to separate blocks of code that you think, as the programmer, 'go together' and between them do one 'thing'.

### Advanced Aside: Variables vs Identifiers

A variable is an identifier, just like the program name. But just because all variables are identifiers does not mean all identifiers are variables! I make this point because people often confuse the two – there are other kinds of identifiers in programs that are not variables. For example, the program name – and others, we’ll see later on.

### Back to the Program…

We’ve been getting away from the example program – so let’s get back to it. The line:

```java
String name = in.nextLine();
```

Creates a variable called  name  and sets it equal (  *assigns*  it) to the value

```java
in.nextLine();
```

This is something called a  *method*  in Java (you might have seen similar things in other languages called functions and/or procedures). It  *returns*  the string of characters that the user types in to the keyboard. So whatever the user types gets assigned to the variable name and ends up stored in it.

### Scanner

You may have noticed we have skipped over two lines in the code:

- The one starting  **import**; and
- The one starting  **Scanner**.

These are necessary to allow us to read input from the user typed at the keyboard - and they are sufficiently complicated that we'll talk about them in the [next section](https://canvas.swansea.ac.uk/courses/68227/pages/1-dot-7-scanner-libraries-and-input-in-java).

#### Declare More than One Variable Per Line (Don't!)

Java does actually let you do things like this:

```java
String givenName = "Neal", familyName = "Harman";
```

That is declare more than one variable on a line - BUT DON'T. This is considered bad style and you should write:

```java
String givenName = "Neal";String familyName = "Harman";
```

You might wonder:

- Why does the language let you do it if its bad practice? That's a good question without a good answer; it's just one of those things.
- Why am I writing  **givenName**  and  **familyName**  in this "weird" way with capitals in the middle and not at the start? We'll get back to that later - its a  *naming convention.*

#### Skip on First Reading if New to Programming: Why do we need to Declare Variables?

Some of you (probably a lot of you) are used to programming languages which don't require you to say what a variable is before you create it - so why do we need to do that in Java. Several reasons for this:

- If you are required to declare a variable  *and* it's type before you can use it, you give the compiler very valuable information - it then knows what you intended to call the variable  *and* what data you intended it to contain.
- So if you later make a mistake (and being human, you will) the compiler is much more likely to be able to find it for you (because it knows more about what you meant).
- The compiler scans the whole program text - so it is 100% guaranteed to find errors (called  *compile-time errors* ). Errors that it doesn't find ( *run-time errors* ) may not show up even after extensive testing (and may be hard to actually then find and fix).
- So catching errors when you compile code is  *far* cheaper and preferable, and leads to far fewer bugs.
- Languages that require you declare your variables (and their type) are mainly meant for larger, more 'serious' applications - those that don't are for shorter, less critical applications (and often targeted at non-professional programmers because the look 'easier').

Having said that, there are of course some different opinions - and some programmers very successfully use languages that don't need you to declare variables (and Java has a way of not requiring you to specify the type - beyond the scope of this module). HOWEVER, since a CRITICAL part of this module is to start to get you thinking carefully and not skipping details; and because most of you are not very experienced programmers (by which I mean you don't have a decade+ of experience), then it's important we stick to a language that does need declarations for now at least.
