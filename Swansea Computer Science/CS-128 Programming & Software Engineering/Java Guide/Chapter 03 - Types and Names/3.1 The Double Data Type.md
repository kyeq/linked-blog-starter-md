# 3.1 The Double Data Type
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/3-dot-1-the-double-data-type)

***Note***  *: some example programs are from, or based on, examples from Java for Everyone (C Horstmann), the course text.*

This chapter is about two subjects we’ve already looked at quite a bit already –  *types* of variables and what to  *call* them. We're going to start of looking at the idea of a data type, and then we're going to introduce our first new one - non-integer numbers called doubles.

## Data Types

A key part of programming is dealing with different types of data – and we use the term  *data type*  to refer to this. So far we’ve seen two – String and int representing sequences of characters and integers. There are others – some of which we’ll deal with in more detail later. Here’s a basic list.

| **Name** | **Examples** | **Notes** |
| --- | --- | --- |
| int | int a = 5; int b = a * 3; | Represents integers, dealt with at length in Chapter 2 |
| String | String value = “hello”; String val2 = value + “ friend”; | Represents sequences of characters, dealt with at length in Chapter 1 |
| double | double pi = 3.1415; double area = pi * radius * radius; | Represents non-integer data |
| boolean | boolean value = true; boolean value = false; | Represents truth values, used in logic to make decisions |
| char | char val = ‘x’; | Represents single characters (as opposed to sequences) |

We’ve already done String and int – we won’t say much about char but we need to talk a bit about the others.

## Double

The data type double represents decimal data. Like int it also has a range of (very similar) arithmetic operators – +, -, *, / etc. (though there is no % - remainder - as this would not make sense). An important point about double is that they are often  *approximations*  because it (potentially) takes an  *infinite*  amount of memory to represent decimals. As an example, consider the fraction 1/3, which is represented by the recurring decimal 3.333333…. – for ever. This needs an infinite number of bits, which is clearly not possible. Similarly, the constant π is an infinite sequence. The consequence of this is that errors can  *accumulate*  over time as you do arithmetic. So you need to be careful and only use it when appropriate (financial calculations for example, are never done using double by banks for this reason).

### Combining Number Types

If you are just using  **double**, or just using  **int**, then there are no real problems – the same operators are available for both  **double**  and  **int**  (except there is no % for double), and the results are mainly what you would expect. There are just a few things to worry about.

### Making Sure a Double is a Double…

Consider the following program:

```java
class DoubleDivideFail {
     public static void main(String[] args) {
          double mystery = 10/4;
          System.out.println(mystery);
     }
}
```

We have declared the variable  *mystery*  to be a double, so you might this this will print 2.5 – but it actually prints 2.0. This is because Java recognizes both 10 and 3 as integers, so it does integer division 10/4 = 2 remainder 2. This not what we want to happen, and there are three ways to fix it. The first is to explicitly force one of either 10 or 4 (or both) to be doubles by writing them as decimals – here’s an example where we have re-written 4 as 4.0:

```java
class DoubleDivide {
     public static void main(String[] args) {
          double works = 10/4.0;
          System.out.println(works);
     }
}
```

The next is to label one of the numbers as a double by putting a  **d**  on the end:

```java
class DoubleDivide2 {
     public static void main(String[] args) {
          double works = 10/4d;
          System.out.println(works);
     }
}
```

There are actually other things we can add on the end to tell Java more about numbers - I'll leave you to look those up yourselves.

The final one is to force Java to change an int to a double:

```java
class DoubleDivide2 {
     public static void main(String[] args) {
          double works = 10/(double)4;
          System.out.println(works);
     }
}
```

We have written (double)4 which forces Java to turn the int 4 into the double 4.0. This is called  *casting* and is an example of forcing one type to turn into another. This is only legal when it makes sense, which it does here. Since in most cases, we are not dividing by ‘simple’ numbers, but by variables, then casting is usually what we have to do. For example:

```java
double works = y/(double)x;
```

where x and y are integers – we cannot just write ‘x.0’ or 'xd'– it doesn’t make sense and won’t compile; but /(double)x does work.
