# 3.3 Representing True and False - The Boolean Data Type
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/3-dot-3-representing-true-and-false-the-boolean-data-type)

Named after the mathematician [George Boole (1815 – 1864)](https://en.wikipedia.org/wiki/George_Boole) - variously said to be English, Irish or British (he was born in England and died in Ireland, then part of Britain). Unlike most other data types, Boolean has only two possible values –  **true**  and  **false**. We use the Boolean type when we need to do logic, which is mainly when we need to make  *decisions* , as we’ll see when we talk about if statements and loops. The Boolean data types comes with a range of operators representing logical operators:

| **Operation** | **Name** | **Meaning** |
| --- | --- | --- |
| !a | Not | If a is true, then !a is false; if a is false then !a is true |
| a && b | And | true if  *both*  a and b are true; false otherwise |
| a \|\| b | Or | true if  *either one*   *or both*  a and b are true; false otherwise |
| a ^ b | Exclusive Or | true if  *either* a or b are true  *but not both* ; false otherwise |

Just like ordinary arithmetic operators, there are precedence rules: first you do the operations in brackets; then any ! operations; then &&; and finally || and ^ (the order of these last two does not matter).  **A common mistake is just using one | or & instead of two - although this seems to "work" they are  *not* the same thing (so don't do that).**

Here are some examples:

```java
boolean a = true;boolean b = true;
boolean c = false;
boolean d = a && b; //This is true
boolean e = a && c; //This is false
boolean f = a || c; //This is true
boolean g = a ^ b;  //This is false
boolean h = a ^ c;  //This is true
```

On its own boolean is not very useful – what we need is a way to create them by comparing data of different types. For example, by comparing numbers. There is a range of operators that are either true or false, depending on the relationship between a pair of numbers - you can see these operators in the table below, and see a video here:

> [!note] There is a video for this on the Canvas page.

| **Operation** | **Name** | **Meaning** |
| --- | --- | --- |
| a == b | Equality | true if a equals b; false otherwise |
| a != b | Inequality | true if a not equal to b; false otherwise |
| a > b | Greater than | true if a greater than b; false otherwise |
| a >= b | Greater than or equal | true if a greater than or equal to b; false otherwise |
| a < b | Less than | true if a less than b; false otherwise |
| a <= b | Less than or equal | true if a less than or equal to b; false otherwise |

Here are some examples where x, y and z are of data type int.

```java
boolean a = (x == y); //true if x equal to y
boolean b = (y > 0); //true if y greater than zero
boolean c = !((z > 0) || (z < 0)); //see below
```

The last one is tricky and you would not really write this because it can be simplified (see below) – but it’s included as a more complex example. The term z > 0 will be true if z is greater than zero; and the term z < 0 is true if z is less than zero – then the term (z > 0) || (z < 0) is true if either z is greater or less than zero – i.e. not equal to zero. However, the ! is applied to the whole expression, so the overall meaning is that c will be true if (and only if) z is equal to zero. In this case of course we would write:

```java
boolean c = (z == 0);
```

Always try to express logic in the simplest way you can - not doing that is another  *Code Smell* which makes your code harder to understand (or course, sometimes people don't always agree on what the simplest way is...)

### KEY POINT - Need Something True or False? Use boolean!

I often get coursework submissions that use numbers (say 1 for true, 0 for false); or Strings (say "yes" or "no") to represent things that should be done using  *boolean.*  **DO NOT DO THIS!**  If you need something that is going to be either *true* or *false,* then you should use *boolean.*

### KEY POINT - = vs ==

A very common mistake to make, which is very natural when you’ve spent many years using ‘=’ for equality, is to write ‘=’ instead of ‘==’. You  **will**  make this mistake sometimes. There is nothing you can really do about this, except practice!

We are going to see a lot more of boolean later on, when we need to deal with  *decisions*  – we won’t often actually declare boolean variables (though sometimes we will), but we will use boolean expressions all the time.

### Common Mistake - Assuming this is Just Like Maths

In mathematics it's possible to write things like this: a < b < c - that is, this is true if b is both greater than a and less than c. This lead to people writing code like this:

```java
boolean z = a < b < c; //does not compile
```

Unfortunately, this won't work - the comparison operators in Java are  *binary* and only accept two arguments.  **Doing this is a very common mistake.**  So you have to write:

```java
boolean z = a < b && b < c; //use the && 'and' operation to combine two tests
```

Boolean vs boolean

Very commonly I get coursework submissions where people use Boolean instead of boolean; and also sometimes Integer instead of int; Double instead of double.

Data types in Java that begin with a capital letter (Double, Integer, Boolean) are the more complex  *class*  versions of the 'simple' types double, int, boolean (and there are a couple of others too). Java uses  *classes*  (which we'll see later) when you need to - potentially - do complex things with data (so String is one for example). When you don't need to do that (which is most of the time with 'simple' data like numbers) it has more efficient non-class types (boolean, double, int). The more complex class versions are provided when you need to do something more complex. It's not a huge problem to use the wrong one, and your program will 'work' because Java automatically converts when it, say, needs to do arithmetic (which you can't actually directly do on Double and Integer) - and we're not so bothered about 'efficiency'. But it is a bit sloppy and better practice to use the simple version unless (pretty unlikely in this module) you really need the capabilities of the complex class version.

### KEY POINT – Comparing Doubles

Above we saw the == operator for checking if two numbers are equal. This works fine for integers, but for doubles it does not; at least not always. Try entering and running this program:

```java
class DoubleError {
     public static void main(String[] args) {

          double r = Math.sqrt(2.0);

          //You would expect r*r==2
          System.out.println(r*r);

          //And this would be true
          System.out.println(r*r == 2);

          //But neither is true

          //And this is the right way
          final double EPSILON = 1E-14;

          //And this *is* true
          System.out.println(Math.abs(r*r - 2.0) < EPSILON);
     }
}
```

We are using the Math library here – Math.sqrt is the square root operator; and Math.abs returns the absolute value of a number. Obviously, mathematically the square of a the square root of a number x are both equal - but that is not happening here, because Java cannot represent the true value of r  *exactly* because double does not have an infinite number of bits – so is  *nearly* equal to 2 but not quite. The way to solve this problem is  *not*  to test if doubles are equal to some value, but instead are  *close enough*  – that’s what the part of the program after the comment //And this is the right way does – it checks to see if the two values are within 1E-14 (10-14, or 0.00000000000001) of each other. That is, if they are close enough allowing for the (inevitable) errors in representation that creep in with arithmetic on doubles.
