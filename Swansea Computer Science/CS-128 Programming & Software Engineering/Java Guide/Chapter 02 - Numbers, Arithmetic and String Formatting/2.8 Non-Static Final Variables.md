# 2.8 Non-Static Final Variables
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/2-dot-8-non-static-final-variables)

In [Section 2.4](https://canvas.swansea.ac.uk/courses/68227/pages/2-dot-4-constants-and-static-final-variables), we introduced  *static final variables -* variables that we declared  *outside* the block stating  **public static void main(String[] args){..** and which could only be set  *once* - after that, they can  *never* be changed. We are using these to represent  *constants* because Java does not have an actual 'constant' keyword of any kind.

It might seem a bit awkward to have to write  **static final** - but there is a point: we can  *also* use the keyword  **final**  *without* using  **static** as well.

The keyword  **final** means 'I am not going to change this again'.

- That obviously applies to constants - once they are set they, by definition, don't change (the clue is in the name...)
- But there is another kind of variable for which this is true - ones that you are using in a computation  *but which you happen not to ever change once you have set them* . These are  *not* the same as constants (though I admit it may take a while to get your head around the difference).

It may seem that this is not likely to be very common and that variables are mainly going to be values that you are going to change at some point (again, the clue is in the name - you would think that variables would vary...). And it is true that a lot of variables do get their values changed while a program executes. But a surprising number don't. Now look again at the Swimming Pool program - none of the variables in that ever change.

We can take advantage of that by using the  **final** keyword, and rewriting our variable declarations. So, for example, we can rewrite this:

```java
int depth = in.nextInt();
```

To this:

```java
final int depth = in.nextInt();
```

And we can do the same with all the other variables we have declared in the Swimming Pool program.

### Why???

Our program still worked before we did this - so why do this? It doesn't seem to get us anything.  **But it does!**

*We are telling the Java compiler something we think is true.*  This has two advantages.

- **Small unimportant advantage** - the compiler might be able to make use of this when it turns Java into code that can be executed to make  *optimisations* that mean the code goes faster.
- **Enormous advantage** - if what we think (that the variable doesn't change)  *isn't* true - the compiler will tell us (with an error message).

Just like declaring variables, the more we tell the compiler about what we think is true about our program, the more checking it can do for us. And the more mistakes that we will find - early on - if what we think is wrong.

So ALWAYS consider if you think a variable is going to change in your program: if you don't think it does, make it  **final.**
