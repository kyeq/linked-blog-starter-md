# 2.3 Case Study: The Swimming Pool Cost Estimator
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/2-dot-3-case-study-the-swimming-pool-cost-estimator)

Now we’re going to work on a bigger example – the swimming pool cost estimator. This is going to be a simple  *straight line* program: one where the calculation just runs from the start to the end without branches or loops. The idea is to work out how much it costs to build a swimming pool. To build a pool you need to:

- **Excavate the space for the pool**  – the cost of this depends on the volume of the pool
- **Line the pool with concrete and tile it** – the cost of this depends on the area of the walls and base of the pool
- **Add in the pumps and machinery**  – for normal-sized pools, this is pretty-much the same: that is, it’s a constant value (as this is an estimate).

Notice we have broken this down into  *stages.*

Our first task is to work out an  *algorithm*  for the calculation:

1. Work out the  *volume*  of the pool – length * width * depth - and multiply the cost per unit volume (we’ll use m3) to get the cost of excavation
2. Work out the  *area*  of the walls and base to get the cost of lining and tiling. This breaks down into smaller steps:
		1. Work out the area of a long side (length * depth) – but there are two so multiply by two.
		2. Work out the area of the short side (width * depth) – again multiply by two.
		3. Work out the area of the base (width * length).
		4. Add the areas together and multiply by the cost per unit of area (we’ll use m2).
3. Finally, add up the excavation and lining/tiling costs, and the pool machinery cost, to get the final estimate.

### Strategy

Of course, there is also a step before these – read in the width, depth and length of the pool; and one after too – printout the estimate. But we’re not going to do it in that order – we’re going to build it in  *stages*  starting with the calculation code.  ***The first thing you need to do to solve programming problems is to break them down into smaller parts***.

### KEY POINT – Build Programs in Stages and Not from the Beginning

Usually, it’s  *not*  best to just start a program at the start – instead, break it down into parts, and build the parts you can  *test* . Then put them together to build the whole program. It’s always easy to test a small part of a program in comparison to a whole, large one.

In this case, we’re going to work on the calculations first. Obviously, in the final program we need to have read in the values before we can do any calculations – but for now we’ll just use temporary values. Here’s our first program - video first:

### Pool Volume

We are going to start by writing down our algorithms in  *pseudo code* - pseudo code means different things to different people, and for some it means a very specific format and notation: for us it just means "write out what you want your program to do in any mixture of words, symbols, code that makes it easy for you". The idea is to divide up the problem (remember? we said that was the way to do things?) into stages we can solve simply. Once we've done that,  *then* we can turn it into Java.

The first part of the problem we are going to solve is working out the pool's volume. Our pseudo-code is:

**Set the value of the width of the pool.**
 **Set the value of the length of the pool.**
 **Set the value of the depth of the pool.**

 **Set the volume to depth * width * length.**

 **Print out the depth, width, length and volume.**

Notice I've put some blank lines in to split up the 'logical blocks' - the first one is getting the input (the the first three lines logically go together); the second is calculating the volume; the final one is printing out the result - this is a good idea to do in code as well as pseudo-code.  ***Personally*** I don't use pseudo-code much - but I've been programming a  *long*  time. You however might want to use it - especially if programming is new to you - to stop having to think about too many things at the same time.

Now we need to turn the pseudo-code into Java - to start with, we are going to stick to fixed values for width, length and depth: first of all it, makes the code shorter and easier to write for now. Secondly, it makes the testing easier to start with: you don't have to keep typing in your test data every time you run your program and can concentrate on getting the logic right (if you want to test different data, you can always edit you code to change the values).

```java
/* Program to compute the volume of a pool
   This is the first stage of building the pool cost
   estimator program
*/
public class PoolVolume {
     public static void main(String[] args) {

     //Values in metres
     int width = 4;
     int length = 7;
     int depth = 2;

     //Now calculate the volume
     int volume = depth * width * length;

     //Print it out - volume should be 56
     System.out.println("Depth: " + depth +
               " Width: " + width +
               " Length: " + length);
     System.out.println("Volume: " + volume);
   }
}
```

Notice we’ve split the first  **System.out.println**  over three lines, and lined up the components – we don’t have to do this, but it makes it more readable.

Notice also that we've put a block comment at the start of the program, and shorter ones using the //style  *in front of* each logical block of code (if we needed to write longer comments here, I would use the /*..*/ style).

Enter this program and run it – it should print out the values of depth, width and length, and the volume 56. Because we've given the depth, width and length fixed values for now, it's easy to test .

### Aside – Testing - Know the answer  *before* you test!

It’s easy to think that once your program compiles and runs, then it’s correct. But in most cases, programs do not initially do what they are supposed to do, and contain logic errors. For example, if we had put this line in:

```java
int volume = depth * width; //left out length!!
```

then we are going to get the wrong answer even though the program ‘works’. You should always run test cases on your program – the number (and way) you do this will depend on how sophisticated it is.  *But minimally you should always know what the right answer is before you start.*

#### Aside - Testing 2

Most programs need to be tested on a wide range of values - and one (common) way to do that is to write test code that reads input from the user; something that seems to be commonly taught in programming in schools and colleges  ***- but this is a very bad idea***. This is for three reasons.

- It usually takes a while to write the code - you need to set up a scanner, print out prompts for the input data, maybe check the input data is legal etc.
- It usually takes a while to run the code - for every test the user needs to type in the data (which discourages them from running many tests).
- It's simply not systematic - the data you enter is on the whim of the user and they are unlikely to do this consistently and systematically.

Much better is to test on a set of  *fixed* values.

- It's usually quicker to write (you can often do it using cut-&-paste quite quickly.
- You can run it very quickly - you just run the program and it automatically runs the tests (no typing values by you).
- You can think though a consistent set of test data that you will always use and which will test for things that you expect to be an issue (e.g. if you are dealing with a program that needs numbers as input, then test for positive, negative and zero values).
- You know the expected result - so instead of reading the output and trying to work out if it's right, you can put in test code that checks if it's correct or not (and prints 'pass' or 'fail' for example).

#### Excavation Cost

Computing the volume is only part of the process – we need to compute the actual  *cost* . To do this, we need to multiply by the cost per m3. Let’s just assume that this is £20/m3. Again, video first:

### KEY POINT – Data Values in Java have no Units

Notice we’ve talked about values in £ and in m3 – but Java does not know anything about these units. We must keep track of these ourselves. In this case, if we assume that depth, length, width are in metres, and we multiply them together; and then multiply by £20/m3 the final value will be in £ - but as far as Java is concerned, it’s just an integer.

### Pool Excavation Costs

Now we extend our program to calculate the excavation costs.

```java
/* Program to compute the cost of excavating a pool
   This is the second stage of building the pool cost
   estimator program
*/
public class PoolExcavationCosts {
     public static void main(String[] args) {

     //Set to specific values for now
     int width = 4;
     int length = 7;
     int depth = 2;

     //Now calculate the volume
     int volume = depth * width * length;

     //Print it out - volume should be 56
     System.out.println("Depth: " + depth +
                " Width: " + width +
                " Length: " + length);

     System.out.println("Volume: " + volume);

     //Work out cost of excavation
     int cost = volume * 20;
     System.out.println("Cost: " + cost);
   }
}
```

Notice we’ve updated the comments and changed the name of the program to reflect the new, slightly changed, function – i.e.  **we’ve done it properly!**
