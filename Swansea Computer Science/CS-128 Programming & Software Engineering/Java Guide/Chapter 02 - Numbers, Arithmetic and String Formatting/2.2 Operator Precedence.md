# 2.2 Operator Precedence
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/2-dot-2-operator-precedence)

You can of course combine operations together:

```java
aValue = 9 * 3 + 4; //if we’ve already declared aValue

```

which evaluates to 31 – (9 * 3) + 4 – because Java obeys the usual rules of operator precedence (commonly called BIDMAS in UK schools). If you want to change this so that the terms you want to be computed first are in brackets:

```java
aValue = 9 * (3 + 4); //This time evaluates to 63

```

I’m going to basically assume that you know this stuff because it’s in the Mathematics syllabus of every educational system in the world, and you must have done it before you got here – in the UK we normally use the  *acronym*  **BIDMAS**  to remind people of the order:  **B** rackets,  **I** ndices,  **D** ivide, **M** ultiply,  **A** dd,  **S** ubtract - but you might have seen BODMAS (Brackets, Orders, Divide, Multiply, Add, Subtract) or PEMDAS (Parentheses, Exponents, Divide, Multiply, Add, Subtract) instead: they are all the same with some different words. ### Unary Minus

Another operator we need of course is  *unary minus*  – to change the sign of a value:

```java
aValue = 4;
anotherValue = -aValue; //anotherValue is now -4
```

### Advanced Aside

It’s called  *unary*  minus because it only applies to  *one*  argument (value) – hence unary (meaning one). The other arithmetic operators - +, - etc. – are  *binary*  operators, because they need two arguments.

### Extra Shortcut Operators

These operators are of course all we need to do arithmetic – but language designers noticed long ago (the late 1960s) that expressions like this were common:

```java
aValue = aValue * 3;
aValue = aValue + anotherValue;
aValue = aValue - 1;
aValue = aValue + 1;
```

To make these quicker to write (and also to make it easier for compilers on the old, slow machines back then), they introduced some extra short-cut operators.

**NOTE THOUGH**  that the order of operation is  *not* the same for these operators - so, for example,  **aValue *=3 + 4 - 2;** will multiply aValue by 3 + 4 - 2 (=5) - it will  *not* multiply  **aValue**  by 3 and then add 5.

The  *unary increment and decrement operators*  ++ and –- add and subtract one:

```java
aValue--;  //the same as aValue = aValue - 1;
aValue++;  //the same as aValue = aValue + 1;
```

The binary operators +=, -=, *=, /=:

```java
aValue *= 3; //the same as aValue = aValue * 3
//next one is the same as aValue = aValue + anotherValue
aValue += anotherValue;
```

In practice, these are pretty handy: ++ is especially commonly used because we often use variables to  *count* things.

### Operator Summary

To summarise all the operators so far:

| **Operation** | **Meaning** |
| --- | --- |
| a + b | Addition |
| a - b | Subtraction |
| a * b | Multiplication |
| a / b | Division |
| a % b | Remainder |
| -a | Unary minus – change sign of a |
| a++ | Add one to a |
| a-- | Subtract one from a |
| a += b | Add b to a |
| a -= b | Subtract b from a |
| a *= b | Set a to a * b |
| a /= b | Set a to a/b |

### Advanced Concept and Dangerous Issue - ++ & --

In the table above we have listed the  **++**  operator and the  **--**  operator coming  *after* the variable they are incrementing/decrementing:  **a++;** and  **a--;**  But you can also write them  *before* the variable:  **++a;**  and  **--a;** So what's the difference?

- **Short answer**  - if you use them  *on their own* there isn't one. So the statements  **a++;**  and  **++a;**  are the same (and the same for the **--**  versions).
- **Longer and dangerous answer**  - if you use them  *as part of a more complex expression they ARE different.* So, for example, assuming that  **a**  has the value 5: after the statement int  **b = 5 * a++;**   **b**  will have the value 25 - because we do the  **a++**   *after* the assignment to  **b**. BUT if you write  **int b = 5 * ++a:**  then  **b** will have the value 30 because the  **++**  happens  *before* the assignment to  **b**. If you think this is confusing, then you are right - imagine for example something like  **int b = 5 * ++a * a++ - --a;**  - what happens when? It's essentially  *intractable* to solve things like this in a clear way, and an example of what we will later call a [code smell](https://canvas.swansea.ac.uk/courses/68227/pages/2-dot-9-code-smells-technical-debt-and-refactoring). I STRONGLY suggest you only use  **++** and  **--**  *on their own* , and  *only*  use the version that comes  *after* the variable. (These operators have actually been removed from Apple's Swift programming language, essentially for this reason.)

### The + Sign – Using it Twice…

In the last chapter we used + to join strings together. Now we’re using it again to add numbers. How is this possible? The answer is that provided Java can understand what  *type*  of data you’re applying it to, it can work out which operation you are doing. So if the things on either side of the + sign are Strings, it joins them; if they are numbers, it adds them. And if one is a number and one is a String, it also joins them (though it can get a bit confused about this and you sometimes need to put in  *brackets* (..) to force it to do the right thing). Using an operator symbol like this in more than one way is called  *overloading.*
