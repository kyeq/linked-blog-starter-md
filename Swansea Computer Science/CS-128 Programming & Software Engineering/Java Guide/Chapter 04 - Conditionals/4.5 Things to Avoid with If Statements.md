# 4.5 Things to Avoid with If Statements
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/4-dot-5-things-to-avoid-with-if-statements)

If you read text books on Java programming they will tell you that you can write an if statement like this:

```java
if (condition)
     statement;
```

where ‘statement’ is a single statement –  **notice we’ve left out the {..}**. These books might also tell you that you can do this:

```java
if (condition) statement;
```

***But you must never do this!***  Here’s why. Suppose you start off with code like this:

```java
if (fruit.equals("Lemon"))
     System.out.println("My favourite!");
else
     System.out.println("Not as good as Lemons...");
```

This is syntactically correct and works – but if you change it to this (because you forgot to put the brackets in now there are two lines of code):

```java
if (fruit.equals("Lemon"))
     System.out.println("My favourite!");
     System.out.println("Better than oranges.");
else
     System.out.println("Not as good as Lemons...");
```

It won’t compile – because Java does not recognize that the two statements

```java
System.out.println("My favourite!");
System.out.println("Better than oranges.");
```

are grouped together – you’ll get something like this:

**Fruit.java:9: error: 'else' without 'if'**

**else**

To fix it you need to bracket the two lines after the if:

```java
if (fruit.equals("Lemon")) {
     System.out.println("My favourite!");
     System.out.println("Better than oranges.");
} else
     System.out.println("Not as good as Lemons...");
```

You may think this is not so bad – the compile catches the error. But if you don’t have an else but wrote this:

```java
if (fruit.equals("Lemon"))
     System.out.println("My favourite!");
```

and then changed it to this:

```java
if (fruit.equals("Lemon"))
     System.out.println("My favourite!");
     System.out.println("Better than oranges.");
```

You don’t get the intended behaviour  *even though it compiles*  – Java will execute the second line and  **always**  print “Better than oranges”  *regardless*  of the value of fruit. In this case the indenting is incorrect and misleading us – this code should really be written:

```java
if (fruit.equals("Lemon")) {
     System.out.println("My favourite!");
     System.out.println("Better than oranges.");}
```

### KEY POINT:  **Always**  put the {…} in If statements

Even if you only have one line in your if statement, put the {…} in – you will be thankful if (when!) you later change your code. So our example above should correctly be written:

```java
if (fruit.equals("Lemon")) {
     System.out.println("My favourite!");
     System.out.println("Better than oranges.");
} else {
     System.out.println("Not as good as Lemons...");}
```

Newer languages – e.g. Apple’s  *Swift*  – are beginning to insist that the {…} are present in if statements to eliminate this problem.

### KEY POINT: Indenting is for  **You**, not the Compiler

As we stated in Chapter 1, Indenting is to make code readable –  *but the compiler does not pay any attention to it.*  Just laying out your code in the way you want it to work without grouping things together with the {…} will not work.

### Controversial Formatting – Avoid

Another thing you will sometimes see in code is that short if statements can be written on one line. E.g.

```java
if (year % 4 == 0)) {System.out.println("Olympics!");}
```

or even (as seen above):

```java
if (year % 4 == 0)) System.out.println("Olympics!");
```

(but remember what we said about always including the {..}!)

Some like this but I’m not keen and think it’s often not clear, so would prefer you avoided it (you will lose style marks in the courseworks if you do it).  *NOTE this is not the same as the 'folding' that you can get IntelliJ to do to make code you are not currently dealing with less prominent - that's fine.*

### KEY POINT: Which 'Way Around' Should an If - Else go?

Consider the code example below - both if-else statements are intended to do the same thing, but we have switched the if-else statement around in the second one by "inverting" the condition we use: in the first we check if count is greater than zero; in the second that it is less than or equal to zero.

The main point we are making here is that it is common for one half of an if-else to be short (say an error message) and one to be quite long (doing some actual computation).

```java
if (count > 0) {
	//
	//
	// Lots of lines of code
	//
} else {
	System.out.println("count must be at least zero.");
}

//OR...

if (count <= 0) {
	System.out.println("count must be at least zero.");

} else {
	//
	//
	// Lots of lines of code
	//
}
```

**Which is best?**   *Personally*  I prefer the second one because both the if and else are clearly visible within a few lines of each other, and I think it's easier to read. Later when we do Methods we'll see that there is a way to easily fix this but in general,  *if you have a situation where one half of an if-else is a lot longer than the other, try to put the short one first.*
