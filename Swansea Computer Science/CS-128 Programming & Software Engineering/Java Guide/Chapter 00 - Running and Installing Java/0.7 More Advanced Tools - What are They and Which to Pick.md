# 0.7 More Advanced Tools - What are They and Which to Pick.
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-7-more-advanced-tools-what-are-they-and-which-to-pick)

I've mentioned more advanced tools a few times now, so what are they? Essentially I'm talking about IDEs  *- Integrated Development Environments -* that provide 'all in one' program development so you don't need to deal with an editor, the command line etc; you don't need to separately compile your code - that's all done for you (and a lot more). That sounds good: the downside is they can be  *very* complex and sophisticated: a bit like just having learned to ride a bike and then being put in control of an airliner. #### I Don't Do Anything Advanced Yet - Why Should I Change?

I get that it's a new thing to learn - and it takes a little while to learn. But....

- It's easier to learn to ride a bike than drive a car - but you wouldn't commute 50+Km on a bike (most of you anyway).
- (Having said that even if you drive a car it's still handy sometimes to be able to ride a bike - so being about to use the basic tools comes in handy sometimes too - which is another reason I teach you how to do it).
- Much of the complexity of these tools can be ignored to start with - [this section](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-9-getting-and-using-intellij)will get you started with what you really need (which isn't much).
- Once you get used to them, there is  *so* much they can do for you automatically - like help with  *debugging;* automatically filling in imports for Java; automatically formatting and laying out code; automatically telling you how much of your code is being tested; integrating  *unit testing* ; being able to systematically rename, say, a variable in one operation; being able to automatically generate and insert some code - and more.

There are lots of more sophisticated alternatives to just using an editor and the command line. You can get (for Windows, Mac and Linux) for free:

- [IntelliJ IDEA](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-9-getting-and-using-intellij).
- Eclipse.
- Netbeans.
- Visual Studio Code (also Windows, Mac and Linux but personally I find it slow on a Mac) and Coderunner (for Mac users and not free though not very expensive either). These are "intermediate" tools which are less capable (but also less complex) than the others which are 'full' development environments. (Having said that there are lots of plugins for Visual Studio Code especially). It's worth having one of these as well for when you're doing something quick & easy.

These are the main ones - there are others but they only do Java as a bit of an afterthought, if at all (e.g. Apple's Xcode, the Microsoft's 'full' Visual Studio - not Visual Studio Code which is different) so I would pass on them for this module.

### Which Should I Pick and When Should I Change?

#### **Short Answer**

***After about two weeks start using IntelliJ.***

**Long Answer**  - it depends on several things.

- Lots of people get 'stuck' using just Notepad++ (or BBEdit on a Mac) and struggle/refuse to move on. This means they need to do a lot more of the basic things themselves so although it would take them a bit of time to learn something more advanced, after a couple of weeks they would more than get that time back. So I strongly suggest not using Notepad++ etc for  *too* long.
- Having said that, it's well worth experimenting with other tools than just IntelliJ (you are unlikely to get to choose what you want in your career, especially at the start). Like programming languages, it's a lot easier to learn to use a new one once you know one already - in practice there isn't much difference between the 'main' IDEs you can use for Java (e.g. IntelliJ, Netbeans, Eclipse) - or the others you might use for other languages (like Visual Studio or Xcode).

**For these reasons I no longer give any detailed support for anything other than IntelliJ - but you will find a lot of guidance on the internet if you want to use something else.**

### "But I Like Visual Studio Code..."

So a few years ago students told us they preferred IntelliJ (and could we stop using Eclipse please?) So we said yes and re-did all the first year teaching material to use IntelliJ. Then the next lot of students said they preferred Visual Studio Code because they had used it in school/college... We are NOT going to redo them all again (it's a big job) - and in any case I STRONGLY suggest if you are a Visual Studio Code user that you learn to use IntelliJ. The reason isn't that Visual Studio Code is 'bad' - it's that Computer Science and Software Engineering are rapidly-changing areas and you HAVE to be prepared to motivate yourself to learn new things. Similarly if you can already use IntelliJ, I suggest you try learning something else (maybe Visual Studio Code).  **As soon as you say "I'll stick with what I know", you're doomed.....**  (And if you want to learn say Eclipse or Netbeans instead then that's fine -  **just don't stick with what you know...** )
