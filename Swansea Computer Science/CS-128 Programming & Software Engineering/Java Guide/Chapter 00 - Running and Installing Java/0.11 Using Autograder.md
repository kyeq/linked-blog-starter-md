# 0.11 Using Autograder
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-11-using-autograder)

We will be using a tool called [Autograder](https://csautograder.swansea.ac.uk) to mark automatically  *part* of your two coursework submissions.

**You will not have access to this immediately - so don't try yet - it will be set up two to three weeks into teaching.**

The parts that are marked automatically are:

- Does the code compile?
- Does it work and what level of function does it reach (the two courseworks let you attempt different levels of difficulty)?
- Does it pass the style checker?

I'm doing this for several reasons.

- **It's quicker**  - it means that I don't need to spend most of the time marking work trying to find out how you meant it to work - so I can concentrate on feedback.
- **It's fairer** - it will always be consistent.
- **It's transparent** - you will get to see the results of these tests before you submit your work (so you'll know if it's going to pass).
- **It's realistic** - you will in your career write code that's tested by other code (so you'll get used to the fact that real software testing has no mercy...).

There are some parts I cannot automatically test - and I will mark those manually, as normal. I'll also provide you with both a feedback  *rubric*  (a table essentially which sets out what you need to do to get marks in a particular category) and a video about your submission.

#### 0.11.1 So What's the Catch?

There isn't one really - however, this tool runs on a machine (actually virtual machine but essentially the same thing) that is dedicated to this task, but it's not infinitely powerful. Test results do not come back immediately and if there are a lot of people submitting work, there may be delays. For this reason you shouldn't leave the work until the last minute (and there will be a daily submission limit). Regardless, you MUST use Autograder at least once for your coursework submissions (because it generates part of the mark).

#### 0.11.2 Fair Warning

**You will be given plenty of time to complete your coursework and UNDER NO CIRCUMSTANCES will delays caused by waiting for [Autograder](https://csautograder.swansea.ac.uk) to finish testing be considered a good reason for late submission.** You should start and test your work in good time.

#### 0.11.3 Autograder giving you a 502 error?

*UPDATE 25/26 - this seems to be fixed now but just in case I've left this in.*

Sometimes Autograder fails with a 502 (Bad Gateway) error - we believe this is to do with integration with the University's authentication system and is beyond our control. To fix this do one of these things:

1. Clear cache and cookies in your browser - how will depend on what browser you are using (Google - or any other search engine - will tell you). You only need to clear things related to swansea.ac.uk
2. Change browsers - a quick fix if you can't be bothered to do 1 above right now (but it may end up happening with that other browser eventually too).
3. Use a different machine - but see 2 above - the only reliable fix is to do 1 (and you may find the issue comes back and you have to do it again).

#### 0.11.5 Autograder in the Coursework

Autograder will be set up to work in a way that encourages you to think about what you are doing, tries to prevent you from acting in a way that might not be good for your wellbeing, encourages you to solve the actual problem rather than 'just' trying to pass specific tests, and attempts to be realistic.

- **There is a daily limit on the number of submissions.** You will not be able to run the tests an unlimited number of times. This is to stop just making small random changes and retesting all the time - which can overload the server and discourages thinking about what the specific issues are. It's also more realistic (this kind of  *acceptance* or  *regression* testing in industry typically happens on a fixed schedule).
- **The daily limit will reset in the early morning.**  This is to  *try* to prevent people staying up all night as, typically, they will have used their tests up earlier in the day/evening.
- **Some tests are 'hidden'.** Most tests are 'open' in that you can see specifically what went wrong, but some are  *hidden.* This means that although you will be able to see  *if* your code passed them, you won't be able to see  *why not* if it doesn't. This is to prevent people writing code that  *only* passes the tests and doesn't actually solve the problem being asked. (Although we get some concerns about this, it's a lot better than the alternative of not using autograder, when you wouldn't know if you had passed the tests until we marked your work.)
- **You are encouraged to make multiple submissions to autograder.** We  *strongly* suggest that you write your solutions to courseworks in  *stages,* and you submit each stage to autograder. The point of this is to build up a 'history' of 'draft' submissions - this could be very helpful you to, for example, demonstrate you wrote the code yourself. It also minimises your chances of having a non-working solution by the deadline.
