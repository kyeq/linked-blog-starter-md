# 0.10 Using CheckStyle
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-10-using-checkstyle)

One of the key parts of programming is sticking to correct style - and this also is a big part of the marking for both courseworks. Fortunately, there are tools to help you do this - and this and the most used one is called  *CheckStyle.* CheckStyle is a simple example of what is called a  *static analysis tool -* and you will almost certainly be using these a lot if you work as a programmer.

***I will be using this as part of the coursework marking process so it's very important you know how to use it.***

This contains information on how to get and run CheckStyle - which will automatically check your Java code against the usual coding standards. I have supplied two different sets of rules, one for each of the ways of placing brackets in a Java file. You can find the CheckStyle program and the two alternative style files in Canvas below this page. I've relaxed the rules a bit to remove checks that don't make sense for this module (they apply to things we won't do). One side effect of that is that it's a bit unreliable at reporting the length of lines that are too long, but apart from that it picks up a lot of issues.

**To understand what checkstyle it is telling you, watch the video below.**

### The Way that Always Works

If you want to run checkstyle on your own machine - this tells you how in a way that always works (using the command line). The video below will explain what checkstyle is telling you.

For instructions that  *may* work (with other tools) see below - it may be easier for you to use checkstyle with your preferred IDE (but not if you cannot use the correct styles).

- Watch the video below.
- **If you are using IntelliJ then you can install a CheckStyle  *plugin -* see below. This means you don't need to download the CheckStyle application but you  *do still need the the .xml files below.***
- Download the file [CheckStyle.zip](https://canvas.swansea.ac.uk/courses/68227/files/11334115) and unzip (expand) it to extract the two files it contains.
- Choose the appropriate style file for your choice or brackets - either i **nlinebrackets.xml**  (for the style I normally use); or  **separatebrackets.xml**  (for the style when brackets are always on a line of their own).
- ***NOTE**  that for the  **FIRST COURSEWORK** because you will not have done everything you need to do to avoid all style errors, I will supply a modified version of the two files inlinebrackets.xml and separatebrackets.xml - it's important you use these (they are slightly simplified). I know I've already said this above but I do get a lot of questions about it.*
- You can get the most recent CheckStyle jar file from here: [https://github.com/checkstyle/checkstyle/releases](https://github.com/checkstyle/checkstyle/releases) - click on ' **checkstyle**  **-10.xx.jar** ' -  *where xx was 16 when I typed this but may go up as they release new versions.*
- **Alternatively and easier**, download [checkstyle-10.11.0-all.jar](https://canvas.swansea.ac.uk/courses/68227/files/11334131) from the link (also linked after this page in Canvas) - this may not be the latest version (but that's unlikely to be an issue).
- Put the .jar file in the same folder as the code you want to check, along with  *either*  **inlinebrackets.xml**   *or*  **separatebrackets.xml**  - the one you choose will depend on your chosen Java style: if you put the { on the end of a line of code (like me) choose  **inlinebrackets.xml**; if you put them on a line on their own choose  **separatebrackets.xml**.
- Type  *either*   **java -jar checkstyle-10.11.0-all.jar -c inlinebrackets.xml filename.java**   *or  **j***  **ava -jar checkstyle-10.3-all.jar -c separatebrackets.xml filename.java** where  *filename.java* is your code.
- *Obviously if you have downloaded a different version from GitHub the numbers in the name of the file will not necessarily be 10.11.0!!*
- You'll get a report of any style violations which you can then fix - rerun it until it says there's nothing wrong.

IT TELLS YOU HOW TO FIX THE ERRORS YOU ARE LIKELY TO GET**. ### Word of Warning

CheckStyle is not perfect: it can catch some naming errors but not all. So, for example:

```java
int LemonIsAFruit;
```

It can tell this is wrong because it starts with a capital. But it cannot tell that:

```java
int lemonisafruit;
```

is also wrong, because it does not understand the concept of a 'word'.  **So you still need to check this manually.**

**It also cannot spot indenting errors for you either - which is a good reason to use a tool like IntelliJ which can automatically format your code (see sections [0.9](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-9-getting-and-using-intellij),).**
