# 0.1 Running and Installing Java
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-1-running-and-installing-java)

To get the most out of this module, you will want to download and install Java on your own computer. And you should install more advanced tools as the module progresses. This chapter tells you how to install and use Java on your own computer - Windows or Mac. It also tells you how you can run Java online (I don't really recommend that normally but it can be useful in an emergency - for example in the in-class test). As well, it tells you how to install and use more advanced tools - but you may want to skip those parts until you are more comfortable with Java  *(but don't leave this more than a couple of weeks).*   **Unlike the rest of the notes,**  you don't necessarily have to read everything in this chapter.

**IT IS VERY IMPORTANT THAT YOU READ AND FOLLOW THESE INSTRUCTIONS VERY CAREFULLY - Not doing this will at the very least mean you won't be able to run Java and at the worst you will have security vulnerabilities in your machine.**

### Important Point About These Recommendations

There are many ways you can write, edit and run Java programs - but only a limited number of ways of doing that are possible on the University lab machines (you CANNOT install your own software on these). The advice in these section is mainly aimed at making sure that they way Java works on them is not completely alien to you as you will as some point need to use them (for example, the large in-class test in January will REQUIRE you to use the lab machines).

### First... Get Java

IF YOU HAVE DOWNLOADED THE LATEST VERSION OF JAVA (26 OR 27 BY THE TIME YOU READ THIS)  **DELETE IT NOW**!!!

It will  **NEVER**  be updated and will ultimately become a security risk for you.

The first thing you need to do is to actually get the  *Java Development Ki* t for whatever type of machine you have -  **BUT NOT THE MOST RECENT VERSION.** It's essential you get the Java Development Kit (JDK) and NOT the Java Runtime Environment (JRE) - or you will only be able to run Java programs and not write them.

There are several different implementations of the JDK and it doesn't really matter which you use - but the most convenient one  *(unless*  you have a 'Snapdragon' PC - see below) is from the "owners" of Java - Oracle (which is free for individual use):

[https://www.oracle.com/java/technologies/downloads](https://www.oracle.com/java/technologies/downloads)

At the time of writing this (Sept 2026), Oracle have stopped requiring you to sign up for an Oracle account to do this, and there are multiple versions available - exactly what will depend on when you are reading this.

#### So Which Do You Get?

##### **Short version** -  **get Java 25, 21 or 17 - do not under ANY circumstances get any other version!**

**MAKE SURE YOU READ THE SECTION BELOW 'Intel/x64/AMD vs Apple/ARM/Qualcomm/Snapdragon**

**It doesn't  *really* matter if you get 17, 21 or 25 (though the PC labs and our auto grading system have 17 Oracle have now made it a bit more difficult to download it by making it harder to find) - but DO NOT get any other versions (see above). They are meant for experimental development essentially and won't be supported for more than a few months (and therefore are likely to end up being security risks).**

**Just pick the relevant 'JDK' version -  *not*  the 'GraalVM version' (which is meant for very specific enterprise things) if you see that as an option.**

**If you have already got version 25 then make sure you read the IntelliJ section carefully before you start using it.**

##### **Long version...**

It doesn't really matter if you choose Java 25, 21 or 17 as they are all  *long term support* (LTS) versions. Java 17 is used in the lab and by the auto grading system, but there won't be any real problems if you choose 25 or 21 for your own machine. But it's not a good idea to get any other version (like 26 or 27) because support only lasts for a few months on the non LTS versions - after which they are not updated and so are quite likely to become vulnerable to security issues (I am always a bit shocked to see students in the second year, running a non-LTS version of Java that they installed in the first year, which has been a potential security breach on their machines for over a year). There are also two older LTS versions - 8 and 11. They would also work fine, but are really too old to recommend at this point.

You also need to choose the appropriate version for your operating system -  **if you are a Mac user you may want to check [section 0.3](https://canvas.swansea.ac.uk/courses/68227/pages/0-dot-3-install-java-tools-on-your-own-machine-mac) first to check if you already have a version of Java.**

#### Intel/x64/AMD vs Apple/ARM/Qualcomm/Snapdragon

A few years ago manufacturers (PCs and Apple) started introducing an alternative  *processor architecture* to the older x64 (made by Intel and AMD mainly). This is called ARM - made by Apple for Macs (and typically called Mx, where M=1, 2, 3, 4...) and essentially the same thing made by Qualcomm (and branded Snapdragon) for PCs.

**To Check on a PC.**  Snapdragon is very new (about two years as I type this) so it's unlikely you have this unless your laptop is very new and even then most are still NOT Snapdragon. But to check, type 'about' in the search box then choose 'About my PC'. If it says 'x64' in the System type then it's Intel/AMD, if it says Snapdragon (I believe - I don't have one to check yet) it's ARM.

**To Check on a Mac.**  Macs with ARM have been out a lot longer and unless your machine is quite old it probably has one. But to check, click the apple menu and choose 'about this Mac' - if it says Apple Mx (where x is a number) next to chip, it has an ARM processor - otherwise it doesn't.

#### When Downloading Java from Oracle

- If you have an Intel/AMD Windows PC then choose x64 installer ( *not* the other options - you can choose the MSI installer if you want but it's pointless).
- If you have an Apple Mx Mac then choose ARM64 DMG Installer ( *not* the other options).
- If you have an Intel/AMD Mac then choose x64 DMG Installer ( *not* the other options).
- If you have an ARM ('snapdragon') PC then you can't get Java (as I write this) from Oracle (you sort-of can but it's lots of trouble) - I suggest you get [Microsoft's OpenJDK version](https://learn.microsoft.com/en-us/java/openjdk) (which should work fine) - choose the one that says 'Windows AArch64/ARM64 msi'

If you have any doubts, watch the video which covers how to get Java from Oracle -  *remember the video only covers downloading and you need to read the appropriate later sections to get things to actually work.*

> [!note] There is a video for this on the Canvas page.

#### Don't Want to Use Oracle's Version?

There is no real reason for you not to use Oracle's version of Java - it comes with easy to use installers (unlike some others). The University however  *doesn't* because it would have to pay (a lot - you don't though, Oracle is free to use for individuals). Instead it uses the [Amazon Corretto](https://aws.amazon.com/corretto/) version. If you want, you can do - it will behave exactly the same as the Oracle version so there are no problems using it (but then no good reason to pick it either). If you do, then again choose one of 25, 21 or 17. If you use Windows you need to download the  **.msi**  file (the other one isn't an installer). If you use a Mac you need to download one of the  **.pkg**  files - the  **x64**  one if you have an older Intel Mac; the  **aarch64**  one if you have a newer M-series Mac. Just run the installers as normal. (And there are various other versions you can get too - there is not good reason to do that though.)
