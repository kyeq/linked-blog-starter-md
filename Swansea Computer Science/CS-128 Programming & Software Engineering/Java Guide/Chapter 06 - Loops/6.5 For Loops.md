# 6.5 For Loops
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/6-dot-5-for-loops)

The last kind of loop in Java differs in that it’s meant to be used when we  *know*  when the loop starts how many times it will go around. However, things are a little complicated and first we need a bit of history.

### ‘Traditional’ For Loops

The syntax of older programming languages varied but they usually had the same kind of for loops. For example, in  *Pascal* :

```java
for i := 0 to 10 do begin
     (* code *)
end
```

is a loop that:

- declares a variable i;
- that starts at 0;
- ends at 10; and
- executes some code eleven times - notice it starts at zero. Comments in Pascal are between (* and *); and  **begin**  and  **end**  take the place of { and }.

You can also count down in some languages:

```java
for i := 500 downto -20 do
            ...
```

The start and end values can also be variables –  *but you can only count in steps of 1* . This is how most for statements worked, with some variations.  *Notice that it’s only possible with this kind of statement to write for loops where you know at the start of the loop starts how many times it will go around -*  because you need to know the value you need to count up to/down from.  **This is the style of for loop present in most 'older' programming languages.**

### For Loops in Java

The designers of one of the ancestor languages of Java (called C) decided to  *generalise*  for loops and make them more flexible. The syntax is:

```java
for(start; end condition; update {
     code
}
```

In this:

- **start**  is code that will be executed  *once* , immediately before the loop begins.
- **end condition**  is a Boolean condition (like the ones in a while or do loop) – the loop will continue as long as it is true.
- **update**  is code that will be executed at  *the end of every iteration of the loop*  – so if the loop goes round 10 times, it will be executed 10 times.

Rewriting the two older style for loops above we get:

```java
for (int i = 0; i <= 10; i++) {
     //code
}
```

and

```java
for (int i = 500; i >= -20; i--) {
```

- The first part of loop before the first “;” defines the *initial condition*  – in this case it declares an integer variable i and sets the initial value to zero for the first one; and 500 for the second.
- The second part (between the two “;”) defines the  *end*  condition – while the condition is true the loop continues. In the first case it continues looping until i is > 10; in the second until i is < -20.
- The final part is not present in the the older version – it says what happens at the end of each loop. In the first case we add one to i and in the second we subtract one (adding one is the default action in the old style; using ‘downto’ changes that to subtracting one – no other actions are possible in that older type of for loop).

The reason this is more flexible is that  *we can put more or less whatever code we want in the three parts*  (including nothing; see below). The examples above are very common in practice, and are really how for loops in Java (and other languages that were the ancestors of Java) were  *meant* to be used.  **Most of the for loops you write - for now at least - should look like these examples.**  But we can also be more flexible - which can be good, but can be bad (because people abuse it). One example is that we don’t have to count up (or down) by one for each loop. For example, the following code prints out only odd numbers up to END_VALUE:

```java
for (int i = 1; i < END_VALUE; i +=2) {
     System.out.println(i);
}
```

This version skips the even numbers (and it's a completely reasonable way to write a for loop).

This flexibility is very helpful – but also dangerous for two reasons.

**It encourages ‘cleverness’ –**  for example you can re-write the odd number program as:

```java
for (int i = 1; i< END_VALUE; System.out.println(i), i += 2);
```

In this case the “;” at the end of the line is  *deliberate*  – we  *want*  the loop body to be empty because we’ve put all the code in the last part of the for loop. Notice the two parts are separated by a “,” – this is called the  *comma operator*  and can be used to join bits of code in a for loop: but it’s rarely a good idea (so don’t do it). Compressing code like this makes it shorter, and is ‘ingenious’ –and people are often quite pleased with themselves when they think of things like this. But it’s also hard to read (is it obvious to you what it means?) so we don’t want to encourage it.  *Remember programs are read by people and so people need to understand them*  - and stuff like this is often a subconscious way of saying "oh look, you can't understand this but I can, so I'm more clever". It's a bad idea for lots of reasons.

**Also being 'clever' like this blurs the line between for and while loops –**  we’ll talk about this a bit more later – first another example.

### Counting Loops and Off-by-One Errors

Notice that in our example above the value of i starts at zero. But the continues only as long as i is  *less than*  NO_OF_YEARS. This means that the value of i ranges from 0..NO_OF_YEARS-1, so the total number of loops (iterations, or repetitions) is NO_OF_YEARS, which is correct. We could equally change it to:

```java
for(int i = 1; i <= NO_OF_YEARS; i++)
```

where we start with i equal to one and continue as long as it is  *less than or equal*  to NO_OF_YEARS. This means that the value of i ranges from 1..NO_OF_YEARS – which is still equal to NO_OF_YEARS (which is still correct).

It does not really matter which of these you choose – though ‘traditionally’ we start counting from zero in Computer Science so you would normally pick the first one. The thing to avoid though is mixing them up:

```java
for(int i = 1; i < NO_OF_YEARS; i++)
```

In this case, i only ranges from 1..NO_OF_YEARS-1, so there are only NO_OF_YEARS-1 iterations (which is wrong).

```java
for(int i = 0; i <= NO_OF_YEARS; i++)
```

In this case, i ranges from 0..NO_OF_YEARS, so there are NO_OF_YEARS+1 iterations (also wrong).

In both cases the number of iterations is wrong by one – we call this kind of error (which is very common) an  ***off-by-one error***. When writing loops (of any kind) you do need to be careful to ensure that the loop iterations the correct number of times (and not one too many or too few).
