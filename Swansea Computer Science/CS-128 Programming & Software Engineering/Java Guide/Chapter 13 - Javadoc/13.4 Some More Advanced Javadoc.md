# 13.4 Some More Advanced Javadoc
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/13-dot-4-some-more-advanced-javadoc)

So far we've only see the @author, the @param and the @return tags. There are quite a few more we can use. Most of them are not very useful at this stage, so we'll only concentrate on two -  **@link** and  **@see**  - as well as showing how we can embed code examples.

### 13.4.1 @link

One thing you commonly want to do in documentation is link to/refer to some other documentation. A simple way to do that is  **@link** - which creates an  *inline* link. That is, it appears in the text, not in a line/block of text on it's own (we can do that with  **@see,**  just below).

The syntax is:  **{@link thing-to-link-to}**

We generally use  **@link**  to link to other bits of Javadoc, and there are several possible variations:

- To link to another Java class - use, for example  **{@link ClassName}**
- To link to another method (or constructor) in another Java class - use, for example  **{@link ClassName#myMethod(...params...)},**  where ...params... are the parameters of myMethod. (You do NOT have to put the return class/type of myMethod - Java requires all methods in a class that have the same name to have different parameters, so that's enough to unambiguously tell them apart).
- To link to another method in  *the same* Java class - use, for example  **{@link #myMethod(...params...)}**.

### 13.4.2 @see

This is also about linking but (a) it creates a block link - a paragraph starting (in bold) 'see also' followed by the link; and (b) as well as being used in the same way as @link above, it can be used to link to external URLs.

The syntax is **@see thing-to-link-to**  (note for  **@see**  there are no {..}!).

The options are:

- To link to another Java class - use, for example,  **@see ClassName**
- To link to another method (or constructor) in another Java class - use, for example  **@see ClassName#myMethod(...params...)**
- To link to another method (or constructor) in the same Java class - use, for example  **@see #myMethod(...params...)**
- To link to an external URL use, for example  **@see <a href=https://openjdk.org/">The Open JDK Project</a>**

### 13.4.3 Which to Use and When?

*Usually* you would use @link when you are discussing things that are  *directly relevant* to someone's understanding of what they are reading - so in the video and example below for the Bank class, you would need to know about BankAccount to understand everything. You would usually use @see when it's more "by the way, you might find this interesting..." than directly relevant now (but of course you have to use it for external URLs).

### 13.4.4 @inheritDoc

Another one you might find useful, but not yet because you haven't done  *inheritance*  is  **@inheritDoc**. This allows you to say essentially "the Javadoc for this is the same as the Javadoc for that, except for this extra bit...".

### 13.4.5 Embedding Code

Since this is about documentation for other programmers using your code, you often need to include bits of code in the Javadoc. Unfortunately, this can be tricky...

#### @snippet - the good news and the bad news...

This basically solves all problems - you can just put things like this in your code:

```java
{@snippet:
public static void main(String[] args) {
    System.out.println("My snippet example.");
}
}
```

And it will appear correctly in your Javadoc. It's also possible to  *refer* to snippets of code elsewhere so you don't have to repeat code examples. I'm not going to show you that - it's easy to look up online - but I'm 50/50 if it's a good idea (basically we are back to the code and documentation being in separate places, though we do avoid repeating things).

The bad news? It was introduced in Java 18, so it's not on the PCs in the labs, and it's not part of csautograder.

#### <pre> and {@code}

The 'standard' HTML tag to embed code is  **<pre>**...  **</pre>**  So, for example:

```java
<pre>
public static void main(String[] args) {
    System.out.println("My snippet example.");
}
</pre>
```

This works fine in most cases - except if your Java has any 'special' characters that mean something in HTML. So for example, if you have this code:

```java
@Override
public void doSomething() {
    ArrayList<String> myList = new ArrayList<>();
    //..stuff...
}
```

It won't like the  **<..>**  or the @sign. So you need to do things like:

```java
{@code @Override}
public void doSomething() {
    {@code ArrayList<String> myList = new ArrayList<>();}
    //..stuff...
}
```

I.e. you need to put  **{@code...}** around the parts with the problem characters.

This is not ideal - but it does work and you only need to do it when you have  **<..>**  or  **@**  symbols in your code.

Here's the Bank example using Javadoc:

```java
import java.util.ArrayList;
import java.util.stream.*;

/**
 * Class representing a (simple) bank that uses {@link BankAccount} to represent
 * individual accounts.
 *
 * This is based on the example from the course notes.
 * @see <a href="https://canvas.swansea.ac.uk/courses/68227/pages/12-dot-0-introduction?module_item_id=4038847">
 *     Chapter 12</a> for the original example.
 * <p>
 * To create and add an account to a bank, you must first create the account object using either the
 * constructor with an initial balance ({@link BankAccount#BankAccount(String, int)}) or the constructor
 * with a zero balance ({@link BankAccount#BankAccount(String)}). For example:
 *
 *<pre>
 *     Bank myBank = new Bank();
 *     BankAccount newAccount = new BankAccount("My Name", 99);
 *     myBank.addAccount(newAccount);
 *</pre>
 * Will create an empty bank, a new account with balance 99, and will add the account to the bank.
 *
 * @author neal
 */
public class Bank {

    private ArrayList<BankAccount> accountList = new ArrayList<>();

    /**
     * Create an empty Bank object. This is the only way to create a Bank.
     */
    public Bank() {
        //If we do not include this explicitly, Javadoc warns us
    }

    /**
     * Add a new account to the bank
     * @param account an object of class {@link BankAccount}
     */
    public void addAccount(BankAccount account) {
        accountList.add(account);
    }

    /**
     * Attempt to delete an account. Accounts can only be deleted if the
     * balance is zero.
     * @param account {@link BankAccount} to delete
     * @return true if successfully deleted, false otherwise
     */
    public boolean deleteAccount(BankAccount account) {
        if (account.getBalance() == 0) {
            accountList.remove(account);
            return true;
        } else {
            return false;
        }
    }

    /**
     * Get an account by name
     * @param name The name of the account
     * @return the {@link BankAccount} with the specified name if found,
     * null otherwise
     */
    public BankAccount getAccount(String name) {
        //Note we have just kept the most 'advanced' version of this from Chapter 12
        BankAccount account
                = accountList.stream()
                .filter(a -> a.getName().equals(name))
                .findFirst()
                .get();
        return account;
    }

    /**
     * Return the total amount of money in all accounts in the bank
     * @return total balance of all {@link BankAccount} objects in the
     * bank
     */
    public int totalAmount() {
        int total = 0;
        for (BankAccount account : accountList) {
            total += account.getBalance();
        }
        return total;
    }

    /**
     * Generate a readable string representation of the bank
     * @return a string consisting of readable representations of all
     * {@link BankAccount} objects in the bank, one per line
     */
    public String toString() {
        String accountString = "";
        for (BankAccount account : accountList) {
            accountString += account + "\n";
        }
        return accountString;
    }

}
```
