# 13.0 Introduction
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/13-dot-0-introduction)

*Documentation* is a not very exciting but critical part of programming. We need to write down what we’ve done (and how) so that both we and others can understand it.

- **Programs and code have a long life**  – it’s rare for code to be owned only by one person, or even by one group of people, over its whole life.
- **We forget how our own code works**  – it’s not just other people: given a few weeks we need to relearn how things we’ve written work.
- **We need to explain it to others** - those who  *use* our code as  *libraries* or  *application program interfaces (APIs)* to help write their own code are mainly interested in  *what it does* not  *how it works.* (Also for  *users* for our application - user manuals essentially. But we won't be looking at that.)

In this chapter we are going to look at documentation in general, but mainly at a tool and technique to systematically embed it in our code to explain to those using what it does.
