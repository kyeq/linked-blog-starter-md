# 13.3 Basic Example
> [!info] From the CS-128 notes on Canvas — [open the original page](https://canvas.swansea.ac.uk/courses/68227/pages/13-dot-3-basic-example)

Below is a simple but full example of Javadoc for a class we have seen already - the bank account. This is explained a bit more below

```java
/**
 * Class representing a bank account with a name and an account balance
 * @author neal
 */
public class BankAccount {

    private int balance;
    private final String accountName;

    /**
     * Make a new bank account with a specified name and opening balance
     * @param name the account holder's name
     * @param openingAmount the initial account balance
     */
    public BankAccount(String name, int openingAmount) {
        balance = openingAmount;
        accountName = name;
    }

    /**
     * Make a new bank account with zero initial balance
     * @param name the account holder's name
     */
    public BankAccount(String name) {
        accountName = name;
        balance = 0;
    }

    /**
     * Add money to the account.
     * @param amount the amount to be added
     * @return the balance after adding amount to the account
     */
    public int depositMoney(int amount) {
        balance += amount;
        return balance;
    }

    /**
     * Withdraw money from the account. The withdrawal will only happen if there
     * is more in the account than the withdrawal amount (i.e. no overdrafts)
     * @param amount the amount to withdraw
     * @return the balance after withdrawing amount from the account, or the initial balance
     * if amount is greater than the existing balance
     */
    public int withdrawMoney(int amount) {
        if (balance >= amount) {
            balance -= amount;
        }
        return balance;
    }

    /**
     * Get the account balance
     * @return the balance of the account
     */
    public int getBalance() {
        return balance;
    }

    /**
     * Get the account name
     * @return the account name
     */
    public String getName() {
        return accountName;
    }

    /**
     * Generate a readable string representation of the account
     * @return String in format: "Account name 'name' has a balance of 'amount' where
     * 'name' is the account name and 'amount' is the current account balance.
     */
    public String toString() {
        return ("Account Name " + accountName + " has a balance of " + balance);
    }
}
```

- Only public things!  **Notice we have only added javadoc comments to the  *public* things. The class itself, and the public methods and constructors. You  *can* add Javadoc comments to the private elements but the javadoc tool won't generate output for that (unless you specifically tell it to). In general, i** f you need to comment other things, you should use 'normal' comments. This example is simple enough that I don't think it's necessary.
- **What it does, not how it does it!** We don't put anything in here about how the code works - just what it does. As an aside, I think that's always good practice for comments anyway  *except* when they are specifically to explain how something tricky works.
- **Columns of '*'** We have put in a vertical column of '*' characters (actually IntelliJ did that automatically...). You don't have to do that, but most people do, and the  **javadoc**  tool will work either way.
- **Tags.**  We have included three kinds of tags -  **@author** which should be followed by the author of the code;  **@param**  for each parameter; and  **@return**  for whatever is returned. Notice these are only present if there is a parameter (and in that case there is one for each parameter) and/or something is returned. So the constructors which don 't return anything do not have  **@return,**  and the 'get' and toString methods don't have  **@param** because they have no parameters.  *The  **@return**  and  **@param** tags are by far the most important to know and use!* There are others we will see, but these are the ones you will use most often.

There is more we can say about this - other tags we can use and good practice to follow. But before we do that, we need to look at how you generate the Javadoc and what it looks like. There is a command line tool for it, but you would mainly these days use your development environment, and we are going to demo it in IntelliJ.

### 13.3.1 Formatting Javadoc

Given that the output is generated in HTML you might wonder: can I use HTML formatting in Javadoc? The answer is you can... but you probably shouldn't (much...)

HTML can help you format Javadoc to make it look better, but:

- **It's pretty good at formatting plain text.** So you mostly don't need to.
- **You need to think about who is reading it and where**  - if it's  *only* via the Javadoc, then fully formatting with HTML can make it readable,  *but usually it ISN'T the only place it's being read.* Usually, some people are reading it in the code too, and in that case, HTML formatting makes it harder to read.
- **There are (some) better ways.**  There are additional tags available (see next section) that you can use instead of HTML that are more readable.

On balance, you should probably try to avoid using 'full on' HTML and only use it when you really have to, to format things in a particular way. Try to strike a balance between the readability of the Javadoc output and the readability of the Javaodc comments in the code.
